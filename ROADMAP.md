# Roadmap

The roadmap describes direction, not a delivery promise. Priorities can change based on accessibility findings and contributor feedback.

## Now

- Stabilize the backward-compatible 2.1 integration and writing-direction candidate.
- Complete a manual assistive-technology pass for forced-colors, high-contrast and mixed-direction content before release.
- Maintain repeatable accessibility, responsive, visual regression, package and commit-identity checks.
- Keep the live visual builder and npm documentation aligned with the packaged CSS API.

## Next

- Collect installation, accessibility and integration feedback from the public 2.0 release and the 2.1 candidate.
- Add localization examples only where concrete consumer needs justify the maintenance cost.

## Later

- Explore a reduced core build and optional theme bundles.
- Consider community-maintained adapters only where they do not fragment the CSS API.

## Completed in 2.0

- Published the first npm package and annotated GitHub release with provenance, checksums and an SBOM.
- Published the canonical HTTPS visual builder with GitHub Pages.
- Validated installation from the packed and registry-published package.

## Completed in the 2.1 candidate

- Added maintained React, Vue and Svelte integration recipes without runtime adapters.
- Added logical group, split, badge and loading geometry plus direction-aware motion.
- Added builder RTL preview/export and a semantic Arabic integration example.
- Expanded automated forced-colors, high-contrast, RTL and accessibility coverage.

Propose roadmap changes through a feature issue with a concrete user need and maintenance impact.
