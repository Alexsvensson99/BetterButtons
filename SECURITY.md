# Security Policy

BetterButtons is a CSS library and static showcase, but supply-chain, browser and markup vulnerabilities are still taken seriously.

## Supported versions

Security fixes target the latest released major version. Before the first public release, only the current `main` branch is supported.

## Report a vulnerability

Do not open a public issue.

Use GitHub's private vulnerability reporting option in the repository's **Security** tab when it is available. If that option is unavailable, contact the maintainer privately through the contact method on [Alexander Svensson's GitHub profile](https://github.com/Alexsvensson99).

Include:

- the affected version or commit;
- a minimal reproduction or proof of concept;
- realistic impact and attack conditions;
- any suggested mitigation;
- whether and when you plan to disclose the issue.

You should receive an acknowledgement within seven days. Timelines for validation, remediation and coordinated disclosure depend on severity and maintainer availability. Please avoid accessing data that is not yours, disrupting services or publishing details before a fix is available.

## Out of scope

Purely visual preferences, unsupported browsers and issues that require a consumer to intentionally remove documented safety markup are normally handled as regular bugs, unless they create a concrete security impact.
